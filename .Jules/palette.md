## 2026-07-28 - [Accessible Navigation & Sticky Header Intersection]
**Learning:** Single-page applications with sticky headers frequently obscure content when navigating to anchor links. To prevent elements like section headings or the Skip to Content target from being tucked underneath an 80px (h-20) sticky header, combining `scroll-padding-top` (or the Tailwind `scroll-pt-20` utility) and `motion-safe:scroll-smooth` on the root `html` element is an optimal, declarative solution. This maintains smooth keyboard and touch-based focus visibility without necessitating JavaScript-based offset calculations.
**Action:** Always configure `scroll-pt-20` and `motion-safe:scroll-smooth` within the `@layer base` block for sites with fixed headers, and pair with a `<main id="main-content" tabIndex={-1}>` landmark and standard Skip-to-Content link to provide an accessible keyboard navigation baseline.

## 2026-07-28 - [Preventing Keyboard Focus Leaks in Hidden Transitioning Menus]
**Learning:** When using CSS height or opacity transitions instead of conditional rendering for mobile navigation menus, using `pointer-events-none` is not sufficient to prevent keyboard users and screen readers from interacting with hidden elements. Closed mobile navigation items can still be tabbed into, resulting in a confusing keyboard focus trap.
**Action:** Ensure the `invisible` utility (which sets `visibility: hidden`) is conditionally applied alongside `pointer-events-none` when the menu is closed. This completely removes the hidden content from the accessibility tree and keyboard tab order, while still allowing the smooth CSS transition animations to trigger correctly.
